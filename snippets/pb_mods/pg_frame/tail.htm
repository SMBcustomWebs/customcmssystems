CONSENT, HANDED TO THE CLIENT. FIRST SCRIPT ON THE PAGE, DELIBERATELY. utils/consent.htm already resolved the visitor's cookies server-side in head.htm. This publishes that answer as a plain object so client-side code does not re-read or re-parse a consent cookie - one reader, in PHP. It has to sit ABOVE theme.js. bgPlayerInit defers its work to DOMContentLoaded but reads window.ccsConsent when it runs, and its guard treats an absent flag as "not yet wired" rather than "denied". Move this below theme.js and background video silently stops honouring consent. THIS IS NOT THE GATE FOR ANYTHING THAT EXECUTES. Script slots are printed or withheld in PHP; a tag that is absent cannot fire. This object only governs iframes shipped without a src, which are inert until one is set. NO POLICY VERSION HERE, DELIBERATELY. It was published for a while, to fix a client-side fallback that guessed '1' when the banner was absent. The answer is now recorded by the server, which stamps the version itself at that moment - so the client neither knows nor needs it, and the whole mismatch is gone rather than guarded.
