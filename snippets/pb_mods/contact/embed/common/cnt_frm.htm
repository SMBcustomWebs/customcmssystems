What each box is called

The label is what a screen reader announces and what appears above the box. The hint is the faint text inside it.

All three labels come pre-filled and working. You do not have to type anything to put this form on a page. Change any of it you like – you just cannot leave one empty, because an unlabeled field is unusable to anyone on a screen reader.

The faint hints are genuinely optional and start out blank.

 Your Name Email Address 5 + 4 + 3 RATHER THAN 6 + 6 + 4. The message row carries one control the other two do not - how tall the box starts - so it cannot be two equal halves. Widening the label to 5 and trimming the hint to 4 leaves exactly 3 for the height and the row closes. How the boxes look

Left alone, the boxes match every other form on the site – the shared styling lives in assets/css/user.php, so a change there reaches all of them at once.

 3 LEFT ALONE, THE BUTTON IS A ROUNDED PRIMARY ONE READING SUBMIT. That is decided in the router, not here, and it has to be. Hiding a field does not clear it - the value an editor saved before unchecking the box is still in the database and still readable. So the router branches on cnt_btn_cust_opt itself rather than on whether these fields happen to hold something, and ignores every one of them while the box is unchecked. Without that, ticking the box, choosing a lurid green, then unticking it would leave the green button on the page with no visible setting explaining why. Same reason there is no required='1' on the button text - see the note at the top of this file. The router supplies Submit when it is empty.

The send button

These only apply while Customize Submit Button is checked. Uncheck it and the button goes back to a rounded primary one reading Submit, whatever is saved here.

 Submit primary btn THE ICON, AND THE MARKUP IT DEMANDS. _cls/btn-icon-pos.htm emits a complete class PAIR - btn-icon plus the left or right modifier - because every positioning rule in theme.css is written .btn-icon.btn-icon-left, so the base is required for the modifier to match anything. Print it as-is and never prefix it. It also requires the icon to be wrapped in a span carrying btn-brand, INSIDE the button. theme.css positions that span absolutely to draw the tinted icon well; a bare i tag gets no well and sits in the text flow, so the reserved padding shows as a gap. The theme handles that. _cls/btn-icon-pos.htm rather than the older dropdowns/button-icon.htm the utility bars still use - that file emits the modifier alone and leaves the required base to the caller, and its own header says to point new fields here. BARE IN THE GROUP RATHER THAN WRAPPED IN A ROW, matching the two Override Default Text Style checkboxes in content/embed/img_cntn_blk.htm. A single full-width control that decides whether the row below it exists is a switch, not a setting, and the established shape for one here is to let it stand alone between two rows. No Icon emits an empty string, so the func below is a plain truthiness test and the theme guards the span on the same field. A button with no icon chosen prints no empty span. showhide THE CLICKABLE LINK IS ADMIN-PAGE ONLY, and the same address is repeated as plain text in the icon field's desc above. Duplicating the address in a desc is the cheap way to have it in both places; a desc renders as text, so only the admin copy is clickable.
