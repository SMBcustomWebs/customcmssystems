    THE FORM'S OWN CLUSTER - one button, hanging off the left edge of the
    form.

    ONE BUTTON, because there is only one thing here that belongs to the form
    as a whole rather than to a field: how the boxes look. Label visibility
    and color, box size, and the space between boxes all apply to every field
    at once, so there is no single field to hang them on. Each field's WORDING
    is a different matter and lives on that field, to its right.

    CUSTOMIZE FORM FIELDS IS IN THIS WINDOW. Without it the window would open
    onto four controls JavaScript is hiding, with the switch that reveals them
    on a different popup entirely. Ticking it here reveals them in place.

    IT DIMS WHEN THE BOX IS UNTICKED, which is the honest signal: the settings
    behind this button are not currently affecting anything.

    fa-sliders, NOT fa-palette. A palette says "pick a color", and only one of
    these four controls is a color - the other three are whether labels show,
    how big the boxes are, and how much air sits between them. Sliders is the
    plain "adjust these settings" glyph, which is what this window actually is.

    It also has to survive being seen next to its neighbors. fa-fill-drip is
    already the background-color button in the section cluster, so a second
    paint-flavored icon a few inches away was two buttons claiming the same
    job. Nothing else in snippets/pb_mods uses fa-sliders.

    ONE FILE, BOTH TILES, and nothing in it differs between them - which is
    new. It used to carry a hide list naming the seven name-and-message fields
    so the email-only tile would not offer to reword boxes it does not draw.
    Now that each field's controls hang off the field itself, not drawing the
    field is all it takes. The list is gone and cnt_inl_hide with it.

    A GATED GROUP HAS TO BE NAMED IN THE WINDOW THAT SHOWS ITS FIELDS.

    This is the rule that broke this button, and it is worth stating plainly
    because it is not the same rule as "list the controller".

    Two separate things have to be in the form for a conditional to work:

      THE CONTROLLER, because functions.php:4724 only wires a dependency when
      array_key_exists($k, $PAGE->forms[$form_name]) - the controlling field
      has to have been rendered into THIS form. Miss it and the dependency is
      skipped without a word and the func evaluates against the empty default
      declared on it, which in this block always means hide.

      THE THING THAT CARRIES not_active, because that is what the JavaScript
      shows and hides. For the two text rows in the header that is the row,
      and bootstrap-grid.php copies a row's not_active down onto every child,
      so listing the children is enough. FOR A GROUP IT IS NOT. _alter_editable
      returns early unless the type is 'row', so a group's children carry
      nothing - the group itself is the only gate.

    So a window showing cnt_frm_lbl_vis and its three neighbors without also
    naming cnt_look_grp shows four controls that no checkbox can reach. They
    render, they save, and Customize Form Fields appears to do nothing. That
    is exactly what it did.

    Naming the group brings the gate into the window: ticking the box opens
    the four fields in place, unticking folds them away again.

    AND NAMING A CONTAINER MEANS NAMING ITS WHOLE CHAIN. inline_ex.php:116
    only nests a field under its group when that group's name is in the list
    too, so cnt_opt_row comes along for the checkbox and cnt_frm_look_row for
    the four dropdowns.
