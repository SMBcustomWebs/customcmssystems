========================================================================= CONTACT BLOCK - BASIC CONTACT FORM snippets/pb_mods/contact/theme/cnt_basic_frm.html Name, email and message, with an optional heading and up to two lines above. The ordinary contact form. ACCESSIBILITY, and every one of these is a real failure mode rather than a box-tick: LABEL ELEMENTS ALWAYS EXIST, paired to their input by for= and id=. The author can hide them visually; visually-hidden keeps them in the accessibility tree where display:none would not. A placeholder is not a label - it vanishes on first keystroke, most screen readers ignore it as a name, and its grey default fails contrast almost everywhere. autocomplete= lets a browser fill known values. For someone with a motor impairment that is the difference between one tap and typing an address. inputmode='email' raises the @ keyboard on a phone. cms:input has no HTML5 email type, so this is how that is reached. role='alert' on the error summary announces itself the moment it appears. role='status' on the thank-you is polite - it waits for a pause rather than interrupting. The submit is a real button element carrying real text, not an input type=submit with a value, so an icon can sit beside a label. SEO. One heading element, level chosen by the author, h2 down to h6 or a plain paragraph. Never h1 - that belongs to the page. The section is a landmark element. RESPONSIVE. The box width comes from the shared txt-box_size.htm, so this section lines up with every other block on the page. No fixed pixel widths anywhere; spacing is all utility classes. THE FORM NAME IS HARDCODED AND MUST STAY THAT WAY. Couch matches a submission back to the form by this name; a generated one would mean no post was ever recognized. The consequence is that two tiles of THIS type on one page would share a name and both react to one submission - a real limit, worth solving before that layout is ever used. =========================================================================
The wrapper is position-relative and always renders, even with no heading and no lines in it, because a blank text area is exactly when the author needs the button that adds the first heading.
< class="mb-3">>

cnt_inl_hide is set to an empty string HERE rather than left unset. scope global writes to the root, which outlives a tile, so an email-only section rendered earlier on the same page would otherwise leave its hide list behind and blank out the name and message wording on this one. The cluster sits outside cms:form on purpose. Couch runs a form's children twice - once to register the fields and process the post, once to render - and only the second pass is emitted. Nothing here depends on that, and staying outside means nothing ever has to.
DELIVERY. k_email_from and k_email_to are exposed by page.php from config.php, which is the Couch-native way to do this - no address is hardcoded here and none is asked of the author. reply_to is the VISITOR's address, so hitting Reply in the inbox answers them directly. from stays the site's own address: putting the visitor's address in From is what gets mail rejected by SPF and DMARC. THE WHOLE FORM, IN ONE TAG. k_success is not a boolean - tags.php builds it as one "Label: value" line per field, in declaration order, the moment validation passes. It skips the submit button and the hidden CSRF token on its own. Which means the CAPTCHA, or a phone field, or anything else added to this form later arrives in the inbox with no edit here. Hand-listing the fields, which is what this used to do, is a list that goes stale the first time the form changes. The label on each cms:input is what titles each line. Those are bound to the same author-editable wording as the visible labels, so the mail reads in the site owner's own words. send_mail defaults to html='0', which decodes entities and strips tags over the whole body, so the newlines survive and nothing markup-ish gets through.
