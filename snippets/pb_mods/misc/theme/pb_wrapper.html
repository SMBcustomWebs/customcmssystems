=========================================================================== THE TILE LABEL BAR. WHAT IT IS. k_template__tile_label is the label= on the tile's own cms:template, in its blocks/ file. This wrapper is what PageBuilder draws around every tile, and it is ADMIN-ONLY: page-builder.php:452 serves it from K_ADMIN_URL with q=show_tile, inside the editor's preview frame. A visitor never sees any of it. WHY EVERY VALUE HERE IS HARDCODED, ON PURPOSE. This is editor chrome, not site content. It has to read the same on all eight themes, so it must NOT follow any of them. What it replaced was class="text-black", which resolves to var(--ccs-black) - the theme's black, which on Notte and Scuro is near-black text landing on a near-black tile. Same trap as the dashboard list groups. bg-light and text-dark would fail the same way; so would any Bootstrap colour utility, because all of them resolve through theme variables. So: literal hex, inline. #11181f on #eef1f5 is about 15:1 - far above the 4.5:1 that WCAG asks for body text, and it stays there no matter what the site is themed. FONT SIZE IN PX, DELIBERATELY, AND THIS IS THE ONE PLACE THAT IS CORRECT. Everything visitor-facing on this site is rem so it follows the root, which Site Text Size drives, and headings are now clamp() so they scale with the viewport. Neither should touch a label in the editor: the label is a fixed piece of interface furniture and it must not resize when an owner sets the site to Comfortable, or shrink on a narrow admin window. font-family is stated for the same reason - a decorative or script custom body font is a fine choice for a site and a poor one for a UI label. A div, not an h5. h1 through h5 now carry clamp() sizes and inherit --ccs-heading-color, so a heading element here would pick up both. The tile content below has its own real headings; this bar is a caption on the frame, not a level in the document. THE FALLBACK MATCHES COUCH'S OWN, IT IS NOT AN INVENTION. k_template__tile_label is the raw stored value: page.php:1769 prefixes every cms:tile attribute with k_template_, so _tile_label arrives as k_template__tile_label - the double underscore is that prefix meeting the attribute's own. Raw means no fallback, unlike page-builder.php:149, which substitutes the tile NAME for an empty label when it builds the admin's tile picker. Reading the raw value here without doing the same would let the picker show a name while this bar showed a blank, for the same tile. So it falls back to k_template__tile_name, which is the value line 149 uses. Every tile has a label today - 29 of 29 here, 74 of 74 on CCS - so this only matters for a tile written later without one. The old hr spacer is gone - the bar's own margin does that job. ===========================================================================
