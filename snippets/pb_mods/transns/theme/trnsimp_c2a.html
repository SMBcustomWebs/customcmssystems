========================================================================= TRANSITION BANNER - call-to-action links snippets/pb_mods/transns/theme/trnsimp_c2a.html Every class and href printed here was resolved in router/trns_img_smp.inc. Four slots, generated from one template. WHY THE ICON IS RENDERED TWO DIFFERENT WAYS On a BUTTON the icon goes in span.btn-brand. theme.css positions that span absolutely against the button box to draw the tinted icon well, and pairs it with the padding reserved by btn-icon. Left or right is decided purely by the class on the anchor, so the span is always printed in the same place - first child - and never moved. On a LINK there is no button box, so the well machinery does not apply. The icon is a bare i tag with a margin, and it really does move: before the text for left, after it for right. THE EXTERNAL-LINK MARKER is automatic on a custom URL, always on the right, together with target="_blank" and rel="noopener" - the same treatment utlbar/ubr_ctct gives it. The embed hides both icon fields once Custom is chosen, and the router suppresses any icon saved earlier, so the marker is the only icon an external link can ever have. The visually-hidden "(opens in a new tab)" rides along with it. The marker is aria-hidden because it is decoration; this sentence is the part a screen reader user actually needs, and it costs nothing visually. The marker uses the .small utility rather than an inline font-size. Four identical style attributes is four copies of the same rule shipped on every render, and an inline style also outranks any stylesheet override, so it could not be retuned site-wide without editing this file. THE RENDER GUARD tests the label or a RESOLVED icon (tis_icon), not the raw Font Awesome field. On an external URL the router suppresses any icon saved before the destination was switched, so testing the raw field would let a slot with no text still emit an anchor whose only content is the external-link marker - a link with no accessible name at all. The old file opened a .row/.col/.btn-group inside a cms:if but closed it unconditionally, so a single-link banner emitted three stray closing divs. One wrapper now, opened and closed by the same test. =========================================================================
