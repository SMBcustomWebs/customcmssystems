 HEIGHT IS TWO CONTROLS, not one, and the old single control was mislabelled. trns_py_ht was called "Section Height" but it only ever emitted py- on the section - padding on a box whose min-height was 0, so the box collapsed to its content and the padding was the whole story. Choosing a small step made the banner SHORTER, and with overflow-hidden on the section the surplus content was simply clipped. Now: Minimum Height is a floor on the content, Section Padding adds space above and below it. The floor is written to an element INSIDE the padded section, so the two genuinely add rather than the padding eating into the floor under border-box sizing. One gate per line. trns_txt_opt now holds the COUNT, so "show line 3" is simply "the count reached 3" - no separate mode, no repeatable. The old shape was two modes: '1' meant up to two fixed lines and '2' meant a repeatable of many. Lines added to that repeatable were not rendering, and a repeatable is the wrong tool here anyway - a banner wants a handful of individually styled lines, not an unbounded list where every row shares one style. showhide showhide showhide showhide showhide show hide CALL-TO-ACTION, ROW LEVEL. How many, and how they sit together. Every per-button control lives in trns_btn.htm. REMOVED FROM HERE, and why: trns_frmt_c2a_opt (Button / Text Only) - the same choice already exists per button, at the bottom of btn-colors.htm as "Link Only (not a button)". Two controls for one decision meant they could disagree, and the row-level one silently won. Hero has never had it. trns_c2a_sz (row-level Button Size) - now per button, matching hero. It also doubles as the text size, which is why no button carries a text size field any more. trns_c2a_mult_btn_wd - a dead control. Nothing read it; width is per button now. trns_lnk_dvd_opt / trns_lnk_dvd_clr_opt (the "/" or "|" separator drawn between text links) - both were gated on trns_frmt_c2a_opt='lnk', which no longer exists. With button-or-link decided per slot, a row can mix the two, and a divider between a filled button and a text link reads as a rendering fault. Gone rather than left half-wired. The four trns_c2aN_chc funcs moved to trns_btn.htm, so each button's gate sits in the same file as the group it gates. showhide Only meaningful once there are two or more to arrange.
