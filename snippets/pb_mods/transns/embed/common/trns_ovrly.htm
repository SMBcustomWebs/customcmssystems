The previous version of this file carried the message: "IMPORTANT: Page can only have one image overlay set. Page will cascade the last image overlay set to any image on the page with an overlay." That was not a limitation of the design - it was the theme writing .bg-holder.overlay-gradient:before into a plain style block, a GLOBAL selector, so the last banner rendered on the page overwrote every earlier one. The router now scopes every rule to a per-tile id built from cms:random_name, exactly as hero does with local_hero_id, so any number of banners on one page keep their own overlays. INDEPENDENT OF THE IMAGE. The old gate was bg_clr_opt=='img' && ovrly_clr_opt=='gradient', which meant a SOLID overlay could never be configured at all - only a gradient one, and only over an image. An overlay over a flat color is perfectly reasonable, so this is now gated on nothing but its own dropdown. =========================================================================

Layer 3 – Color Overlay

The top layer, painted over both the color and the image. Use it to knock back a busy photo so text stays readable.

 The original reference here was dropdowns/overly-colors.htm - note the missing "a" - and no such file has ever existed, so this dropdown rendered with no options in it at all. Now points at _tok/color-overlay.htm. Two things follow from that. It leads with "No Overlay=" (empty), which per the house rule makes off the default without an opt_selected. And its custom escape stores the value custom, NOT gradient - because bg-gradient is a real class in theme.css, so the old sentinel assembled into working CSS and a missed branch failed quietly. bg-custom matches nothing, so the same mistake now shows itself. A theme color has no alpha channel of its own, so it needs this dropdown or a solid overlay would hide everything beneath it. A CUSTOM color does NOT need it. The color pickers below are declared alpha='1', which puts a real transparency slider on the swatch, so the user sets opacity on the color itself - finer control than this list, and per-color on a gradient rather than one value for both. Showing both controls would mean two transparency settings fighting over one layer. So the func hides this whenever the color dropdown is on Custom, and again on No Overlay where there is nothing to fade. That is exactly what hero does with ccs_hro_ovrly_opc - same rule, same reason. Func sits inside this row, the same level as its slave, matching hero. hide show show hide
