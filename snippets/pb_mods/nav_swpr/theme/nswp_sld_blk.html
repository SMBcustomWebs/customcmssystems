AJAX SHORT-CIRCUIT. A nav click fetches this whole page with ?ajax_module=1, so every nav_swpr tile on the page used to render and the JS discarded all but one. The click now also sends &ajax_block=; any tile that is not the target renders nothing at all - including the router, which is where the folder loop and its per-folder queries live. If ajax_block is absent (stale cached JS) every tile renders, i.e. the old behaviour, so this cannot break a half-updated browser cache. Title and link identify the SECTION, so they follow the configured SOURCE: a specific folder names itself, 'All' names the template. Only the IMAGE follows the ACTIVE category - that is the part that gives feedback about which nav item you are on, and it is all that changes on a nav click. One folder loop serves both lookups. Fallbacks - template title / template root / default logo. NOTE: this must stay ABOVE the ajax branch below - that branch emits promo_img into the response for the JS to pick up, so computing it afterwards would ship an empty value and the image would never update. The AJAX response returns only the slider, so the promo panel would go stale the moment someone clicks. This carries the new category's image, title and link so the JS can update the panel too - otherwise showing the active category would be worse than showing a neutral logo.

Nav side is a genuine DOM reorder, not Bootstrap's order-* utilities. order-* moves a column visually while leaving source order alone, so keyboard tab order and screen-reader reading order would disagree with what is on screen - WCAG 1.3.2 / 2.4.3. Capturing each column and emitting them in the chosen sequence keeps all three in step. nswp-align-* carries the block alignment down to the nav so the depth indent and marker spacing follow the text side rather than being hardcoded left. Alignment itself comes from Bootstrap's text-start/center/end on the elements; this class only handles the directional bits Bootstrap has no utility for.

rewind, not loop. Loop mode duplicates slides to build a seamless cycle and needs roughly 2x slidesPerView real slides to do it - with a fractional slidesPerView and only a handful of products per category it cannot, and leaves blank track. rewind just returns to the first slide at the end, so it works with any number of products. The fractional slidesPerView is deliberate: the sliver of the next card is what tells people the row scrolls, which is the job autoplay used to do badly.
JSON-LD for the products shown. Emitted once, after the slider, and only on a full page render - an AJAX fragment must not carry its own schema block. ItemList rather than bare Product entries: these are a carousel on a category page, not the page's primary subject, which is what Google's guidance asks for. Renders nothing visually.
