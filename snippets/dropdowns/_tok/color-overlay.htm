=========================================================================== snippets/dropdowns/_tok/color-overlay.htm EMITS a bare color token, or the sentinel "custom". USE AS bg-{token} on the overlay layer element VARIANT OF _tok/color-bg.htm - identical tokens, reordered for the job. Per the house rule, a shared file is never edited to suit one use; a variant is made instead. What differs is the running order, which is the only thing that sets the default, since opt_selected is never used. WHY THE ORDER DIFFERS an overlay is nearly always used to knock a busy photo back so text stays readable, so the darks come first. Picking a bright theme color as an overlay is legitimate but rare, so those sit lower. MUST BE GUARDED "No Overlay" emits an empty string. PAIR IT WITH TRANSPARENCY a solid overlay at full strength hides everything under it, which makes the image and base color pointless. Always put _tok/bg-opacity.htm beside this field, not inside the custom-color group - the transparency applies to theme colors just as much as custom ones. CHEAPER ALTERNATIVE FOR PLAIN DARKENING if all that is wanted is "make the photo darker," _cls/overlay-tint.htm does it with a class that already exists in theme.css and generates no per-tile CSS at all. Reach for this file when the overlay needs to be a specific color. THE SENTINEL "custom" is inert as a class on purpose. See the long note in _tok/color-bg.htm for why it is no longer the word gradient.
