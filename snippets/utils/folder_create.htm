============================================================ CREATE A SUBMENU FOLDER FROM THE FRONT END ------------------------------------------------------------ CONTRACT in : fc_masterpage owning template, e.g. 'about.php' (required) fc_title the folder's display title (required) fc_parent parent folder id, '-1' for top level (default -1) fc_weight sort weight (default 0) out : fc_result created | duplicate | denied | invalid | error fc_folder_id new folder's id, on success fc_folder_name its generated url name, on success fc_error message, on failure ------------------ WHY THIS IS NOT A cms TAG ---------------- Because there isn't one. db_persist writes PAGES; nothing in Couch or any addon here exposes folder creation to a template. That is the whole basis of "folders can't be made from the front end" - true of the TAG LAYER, and not true of the class underneath it. The admin's own create path is one line, edit-folders.php: $folder = new KFolder( array('id'=>null, 'name'=>'', 'pid'=>'-1', 'template_id'=>$PAGE->tpl_id), $PAGE->tpl_name, new KError() ); followed by populate_fields(), store_posted_changes() on the system fields, and save(). All of it is reachable from cms:php. This is the same move wishlist-modal.php makes to write a page a level-2 customer could not: use the class, guard it properly. ---------------- THE SUBMENU PAGE IS AUTOMATIC -------------- A folder here is TWO objects: the couch_folders row, and a page named 'folder-' in the template's folder_masterpage (bmenu/about.php and friends) carrying the submenu's hero and pagebuilder. Do NOT create that page. save() fires 'folder_saved', and KExtendedFolders::save_custom_folder_fields (addons/extended/ extended-folders.php) builds it, names it and publishes it. Creating one by hand would give the folder two. ------------------------- $PAGE ------------------------------ KFolder::save() reads the $PAGE GLOBAL twice - once to lock the template row, once for 'template_id' on the insert - and KFolder::name_unique checks uniqueness against $PAGE->tpl_id. So $PAGE must BE the owning template while save() runs, which it is not when this is embedded in add-about.php. Swapping the global is therefore not a hack, it is the interface. It is swapped back in every exit path, including the failure ones - leaving the wrong $PAGE behind would corrupt whatever rendered next. validate_parent needs no folder tree here: it returns early when $PAGE->folder_id is null, which it is for a new folder. ------------------------- SAFETY ----------------------------- Level 7 with editing on, checked BEFORE the elevation, never inside it. The title is the only thing taken from the browser; 'name' is left blank on purpose so save() derives a clean unique url from the title rather than trusting a posted one - that field's validator is title_ready|KFolder::name_unique and a rejected name would fail the whole save. ============================================================ Positive test, not a negated one. Wrapping get_session in cms:not needs the inner tag quoted, and the outer cms:if attribute is quoted too - so the inner double quote closes the outer one and Couch stops with ERROR! LOGIC_OP: Invalid char "e" Same trap as building a redirect url inline; see the note in users/logout.php. Test for permission and put the refusal in the else.
