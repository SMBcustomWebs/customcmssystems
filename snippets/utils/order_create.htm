================================================================ order_create.htm - write a PENDING order plus its line items. WHERE THIS RUNS Inside checkout.php's cms:form, in the k_success branch. That is not optional: it reads the checkout fields as frm_, and tags.php only populates frm_* for registered cms:input fields inside a successful cms:form. Raw HTML inputs (billing_*, gateway) are read with cms:gpc instead, because they never become frm_*. WHAT IT SETS (all scope='global', so the caller can read them) ccs_new_order_id k_page_id of the created order, '' on failure ccs_new_order_number human-readable reference, e.g. VS-1042 ccs_order_error error text, '' when all went well WHY PENDING The order is written BEFORE the customer reaches the gateway, so there is a record to reconcile against whatever comes back - and something to look up if the customer closes the tab mid-payment. Nothing here marks anything paid. Only order_fulfil.htm does that. EVERY MONEY VALUE IS A SNAPSHOT, per the note at the top of orders.php. Nothing downstream should recalculate from live product data - prices change, orders must not. ================================================================ Billing: if the customer left "same as shipping" ticked, copy the shipping values across so the order carries a complete billing record of its own - orders.php documents this expectation. Totals. pp_sub_total / pp_shipping / pp_taxes / pp_total are TAGS, not variables - the original checkout.php learned this the hard way with k_cart_total. Capture each into a variable first. The four totals fields carry validator='non_negative_decimal'. An empty string is not a valid decimal, and pp_shipping / pp_taxes return nothing at all when no shipping or tax rule applies - which is this site's normal configuration. Coerce to '0' so a free-shipping order can still be saved. global $CTX; foreach( array('oc_subtotal','oc_shipping','oc_tax','oc_total') as $k ){ $v = trim( (string) $CTX->get($k) ); if( $v==='' || !is_numeric($v) ){ $v = '0'; } $CTX->set( $k, $v, 'global' ); } ---------------------------------------------------------------- STEP 1 - create the order shell. No k_page_title and no k_page_name are supplied, so db_persist's _auto_title path assigns a random md5 for both. That is deliberate on two counts: a per-order unique page_name is guaranteed without us inventing one, and the resulting URL is unguessable. The readable title is written in step 2, once we know the id. ---------------------------------------------------------------- _auto_title='1' is REQUIRED, not decorative. data-bound-form.php declares the default as '_auto_title'=>'0', so without it no title and no page_name are generated, the save fails validation, and k_last_insert_id never gets set - which surfaces later as "db_persist - _page_id required". ccs_auth_uid, not k_user_id. k_user_id is overwritten by the extended-users addon with the users-template page id, so it can be the real user id, a page id, or -1 depending on install state - and which one you get changes when a template is registered. An order tagged with it can stop matching its own owner later. utils/auth_uid.htm has the detail; head.htm sets ccs_auth_uid, and checkout embeds head.htm well before this runs. Empty for a guest checkout, which is correct. order_user_id=ccs_auth_uid order_first_name=frm_first_name order_last_name=frm_last_name order_email=frm_email order_ship_address=frm_address order_ship_city=frm_city order_ship_state=frm_state order_ship_zip=frm_zip order_bill_address=oc_bill_address order_bill_city=oc_bill_city order_bill_state=oc_bill_state order_bill_zip=oc_bill_zip order_subtotal=oc_subtotal order_shipping=oc_shipping order_tax=oc_tax order_total=oc_total /> Capture db_persist's own outcome IMMEDIATELY, before anything else can touch the context. Gating on k_success is not safe here: this snippet runs inside checkout.php's cms:form, which has already set its own k_success, so a failed create can leave the outer '1' visible and send us down the success path with no id. The presence of an insert id is unambiguous. The random page_name db_persist just generated becomes the order's confirmation TOKEN. order-complete.php is addressed by this rather than by the sequential page id, so a customer cannot walk ids and read other people's names, addresses and order contents. STEP 2 - stamp the reference. order_number is its own indexed field (search_type='text') so a gateway callback can find the order without depending on how Couch slugified anything. k_page_title gets the same value purely for a readable admin list. ------------------------------------------------------------ STEP 3 - one order-items page per cart line. Line items are a sibling template rather than a mosaic because db_persist only writes keys present in $pg->_fields, and mosaic tiles are separate pages - order-items.php explains this. Inside cms:pp_cart_items the canonical vars are line_id, id, name, title, link, price, quantity, line_total and requires_shipping (cart.php, cart_items_handler). tax_class and tax_rate are added on top by cart_ex.php's cart_alter_custom_fields listener. ------------------------------------------------------------ SKU snapshot. itm_sku is optional - its own description says "leave blank to use a system-generated ID" - so fall back to the product's page id, which is unique by construction.
