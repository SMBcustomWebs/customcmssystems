============================================================ NEW CATEGORY - the POST handler. ------------------------------------------------------------ CONTRACT in : fh_masterpage owning template, e.g. 'about.php' fh_page this add page, e.g. 'add-about.php' out : fc_result '' when nothing was submitted, else created | duplicate | denied | invalid | error fc_error message when it failed fc_made the title just created, on the GET that follows a successful create WHERE TO EMBED At the very top of an add-*.php page, BEFORE any markup - it redirects on success, and output already sent makes that a header warning rather than a redirect. ---------------- POST / REDIRECT / GET ---------------------- Not optional. Without it the browser keeps the POST in its history and a refresh re-submits, creating a SECOND folder - and because KFolder::save() derives a UNIQUE url name from the title, the duplicate never collides. It is accepted in silence, leaving two identical submenu entries with two bmenu pages behind them. The confirmation therefore has to survive a redirect, which is what the flash is for - the same pattern users/register.php uses after creating an account. get_flash consumes it, so a second refresh shows a clean form. Only SUCCESS redirects. An error has nothing to re-submit by accident and its message has to stay on screen beside the form that produced it - folder_dialog.htm re-opens itself when fc_result is set for exactly that reason. The destination keeps ?pid= when present, so adding a category midway through editing an item does not throw the editor away. ============================================================ Assign, then compare.
