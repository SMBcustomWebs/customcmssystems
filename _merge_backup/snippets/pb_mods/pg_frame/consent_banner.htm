IT LIVES IN THE FRAME, NOT IN A PAGEBUILDER TILE, AND THAT IS DELIBERATE. PageBuilder caches a tile's rendered HTML in one entry shared by every visitor (page-builder.php:265). A consent banner is per-visitor by definition - cache it and one person's answer is served to the next. The frame embeds this file directly on every request, so it is always resolved against the cookie the current visitor actually sent. IT RENDERS ONLY WHEN THERE IS A QUESTION TO ASK. Two gates: the owner has switched the banner on, and this visitor has not already answered for the current policy version. TURNING THE BANNER OFF DOES NOT TURN TRACKING ON. If the owner unticks the setting, consent is simply never granted, so the gated script slots stay empty. Off means "ask nobody and load nothing", never "assume yes". That is the only safe direction for a switch like this to fail in. REFUSING IS EXACTLY AS EASY AS ACCEPTING. Both are one click, side by side, same size, same weight, neither styled to look like the sensible one. This is a legal requirement in every opt-in regime, and it is also the honest way round. There is no close button: dismissing a consent prompt is not an answer, and treating it as one would be recording consent nobody gave. ACCESSIBILITY. The bar is a labelled dialog with its description wired through aria-describedby. Focus moves to it once so a keyboard or screen reader user meets it rather than tabbing past it, and the browser's own focus ring is left alone. Escape deliberately does nothing - there is no silent way out, by design. =========================================================================== The globals fields are NOT ambiently in scope in the frame - head.htm has to reach for them one at a time with get_custom_field. Opening globals once here puts every ccs_gl_ field this banner needs in scope together, which is both cheaper and less error-prone than a dozen separate lookups. ccs_consent_set and ccs_consent_ver come from utils/consent.htm and were set with scope='global', so they survive into this block rather than being shadowed by it. NO cms:else FALLBACKS IN THIS FILE. Every string the bar prints is a required field in globals.php carrying a real default in the body of its editable, so get_data() returns the default whenever the field is empty - on the front end and in the panel alike (field.php:363). A second copy of the wording hidden here would be a value nobody could see or edit, and the two would drift.

Privacy Policy · Cookie Policy

Reject is listed FIRST and carries identical styling to Accept. A "reject" that is smaller, greyer or one level deeper than "accept" is the specific dark pattern that regulators have been fining people for.
Necessary is shown, checked and disabled rather than hidden. People are entitled to see everything that is being set, including the part they cannot decline, and hiding it invites the suspicion that something else is hidden too.
